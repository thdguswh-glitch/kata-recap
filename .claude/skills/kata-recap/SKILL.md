# 카타 정리

아티클 카타가 끝난 뒤, 원문과 팀원 정리를 바탕으로 회차 요약을 만든다. 출력은 한국어로 쓴다.

## 원칙

1. **출처별 기준을 지킨다.** 요약과 핵심 논지는 원문 기준으로, 논의 포인트와 인사이트는 팀원 정리 기준으로 쓴다.
2. **논의되지 않은 내용을 논의된 것처럼 쓰지 않는다.** 원문에만 있고 팀원 중 아무도 짚지 않은 내용은 논의 섹션에 넣지 않는다.
   - 2-1. 논의하지 않은 주제와 내용을 생성하지 않는다.
   - 2-2. 팀 논의 중 결론이 나오지 않은 내용을 찾아준다. 팀원 정리에서 의견이 갈렸거나, 질문만 남았거나, "더 이야기해 보자"로 끝난 부분을 "결론이 나지 않은 논점"으로 따로 정리한다. 결론을 대신 내리지 않고, 팀원 정리에 근거가 있는 것만 적는다.
3. **팀원 정리가 원문과 다르면 원문을 따르고, 다르다고 알려준다.** 어떤 부분이 어떻게 다른지 사용자에게 밝힌다. 팀원 정리를 조용히 고치지 않는다.
4. **비슷한 의견은 하나로 묶고, 질문과 개인 경험은 따로 살린다.** 여러 명이 비슷하게 말한 건 한 항목으로 합치고 괄호에 이름을 적는다. 질문과 개인 경험은 합치지 않고 말한 사람 이름과 함께 남긴다.
5. **원문만 받았다면 요약만 먼저 쓴다.** 팀 논의는 지어내지 않는다.

## 입력별 동작

- **원문만 있을 때:** 요약과 핵심 논지만 쓴다. 팀 논의 섹션은 "팀원 정리가 아직 없음"이라고 쓰고 비워 둔다. 정리를 받으면 이어서 완성하겠다고 안내한다.
- **원문과 팀원 정리가 모두 있을 때:** 아래 출력 구조 전체를 쓴다.
- **팀원 정리만 있을 때:** 논의 섹션만 쓰고, 요약과 핵심 논지는 "원문이 없어 생략"이라고 표시한다.

## 출력 구조

```
# [회차/아티클 제목] 카타 정리

## 요약
(원문 기준. 3~5문장)

## 핵심 논지
(원문 기준. 불릿 2~4개)

## 논의 포인트
(팀원 정리 기준. 비슷한 의견은 묶고 괄호에 이름. 예: "~라는 의견 (민수, 지은)")

## 인사이트
(팀원 정리 기준. 논의에서 나온 시사점, 적용 아이디어)

## 결론이 나지 않은 논점
(팀원 정리 기준. 의견이 갈렸거나 질문만 남은 부분. 결론을 대신 내리지 않는다)

## 질문·개인 경험
(묶지 않고 말한 사람 이름과 함께)

## 원문과 다르게 정리된 부분
(있을 때만. 원문 기준으로 바로잡은 내용과 이유)

## 원문에는 있지만 논의되지 않은 내용
(있을 때만. 한두 줄로 짧게. 논의된 내용이 아님을 제목에서 분명히 한다)
```

해당 내용이 없는 섹션은 빈 칸으로 두지 말고 통째로 생략한다. 단, 입력이 부족해서 비운 경우에는 "입력별 동작"의 안내 문구를 쓴다.

## 작성 지침

- 팀원 이름은 정리에 적힌 그대로 쓴다. 이름이 없으면 "한 팀원"처럼 쓰고 추측하지 않는다.
- 팀원 정리에 없는 의견, 수치, 결론을 덧붙이지 않는다. 확실하지 않으면 사용자에게 물어본다.
- 원문의 표현을 길게 옮기지 말고 요약한다.
- 형식 예시가 필요하면 `references/예시.md`를 참고한다. 이 파일이 없어도 위 구조만으로 작성할 수 있다.
